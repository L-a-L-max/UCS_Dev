## 1. 概述

本文档描述如何在一台全新的虚拟机（Ubuntu 22.04/24.04）上，从零开始拉取 UCS 平台代码并使用 Docker 启动所有 `ucs-platform` 微服务，进行基础功能测试。

**启动范围：**
- ✅ `ucs-platform/` 下的 7 个 Spring Boot 微服务（通过 Docker Compose 编排）
- ✅ 基础设施：Kafka、Redis、PostgreSQL、TimescaleDB
- ✅ 前端 React 应用（开发模式，局域网可访问）
- ⚠️ DDS Gateway（可选，需要 ROS2 环境）
- ❌ 不包含 `backend/` 目录的内容

**整体架构：**

```
┌─────────────────────────────────────────────────────────────┐
│                      Docker Network (ucs-net)               │
│                                                             │
│  ┌──────────┐  ┌──────────┐  ┌───────────┐  ┌───────────┐  │

│  └────┬─────┘  └────┬─────┘  └─────┬─────┘  └─────┬─────┘  │
│       │              │              │              │         │
```

## 2. 环境依赖

### 2.1 硬件要求

| 资源 | 最低要求 | 推荐配置 |
|------|---------|---------|
| CPU | 4 核 | 8 核 |
| 内存 | 8 GB | 16 GB |
| 磁盘 | 40 GB | 80 GB（SSD 推荐） |

> Docker 镜像构建 + 运行 7 个 JVM 微服务 + 4 个基础设施容器，内存消耗较大。

### 2.2 软件要求

| 软件 | 版本要求 | 用途 |
|------|---------|------|
| Docker | 24.0+ | 容器运行时 |
| Docker Compose | v2.20+（Docker 插件版） | 容器编排 |
| Git | 2.25+ | 代码拉取 |
| JDK | 17 | Maven 构建（构建阶段） |
| Maven | 3.8+（或使用项目自带 wrapper） | 编译打包 |
| Node.js | 18+（推荐 20 LTS） | 前端构建运行 |
| npm | 9+（随 Node.js 自带） | 前端包管理 |

> **DDS Gateway 额外依赖（可选）：** Python 3.10+、ROS2 Humble、px4_msgs

### 2.3 网络要求

- 虚拟机需要有可被局域网其他机器访问的 IP 地址
- 防火墙需放行以下端口：`5173`（前端）、`8080`（API 网关）
- 需要外网访问权限（拉取 Docker 镜像、Maven 依赖、npm 包）

## 4. 项目结构说明

### 4.1 微服务模块

```
ucs-platform/
├── pom.xml                    # 父 POM，统一依赖管理
├── ucs-common/                # 公共模块（DTO、工具类），不独立部署
├── ucs-api-gateway/           # API 网关 (:8080) — 统一入口、路由转发、JWT 鉴权
├── ucs-telemetry-ingest/      # 遥测接入 (:8081) — 接收 DDS Gateway 上报的遥测数据，写入 Kafka
├── ucs-telemetry-store/       # 遥测存储 (:8082) — 从 Kafka 消费遥测数据，写入 TimescaleDB
├── ucs-realtime-push/         # 实时推送 (:8083) — 从 Kafka 消费数据，通过 WebSocket 推送前端
├── ucs-command/               # 指令下发 (:8084) — 处理指令确认与状态跟踪
├── ucs-drone-state/           # 无人机状态 (:8085) — 管理无人机在线状态与属性
└── ucs-business/              # 业务管理 (:8086) — 用户/团队/任务/集结点等核心业务逻辑
```

### 4.2 基础设施组件

| 组件 | 镜像 | 用途 |
|------|------|------|
| **Kafka** | `apache/kafka:3.7.0` | 消息队列，KRaft 模式（无需 ZooKeeper）。微服务间遥测数据、指令、事件的异步传输 |
| **PostgreSQL** | `postgres:16-alpine` | 业务数据库。存储用户、团队、任务、集结点等业务数据 |
| **TimescaleDB** | `timescale/timescaledb:latest-pg16` | 时序数据库。存储无人机遥测历史数据（位置、高度、速度等） |
| **Redis** | `redis:7.2-alpine` | 缓存。JWT Token 黑名单、无人机实时状态缓存、分布式锁 |
| **Kafka UI** | `provectuslabs/kafka-ui:latest` | Kafka 可视化管理界面（开发调试用） |

### 4.3 端口分配总览

| 端口 | 服务 | 说明 |
|------|------|------|
| 5173 | 前端 (Vite) | React 开发服务器，局域网访问入口 |
| 8080 | ucs-api-gateway | API 网关，前端 API 请求统一入口 |
| 8081 | ucs-telemetry-ingest | 遥测数据接入 |
| 8082 | ucs-telemetry-store | 遥测数据存储查询 |
| 8083 | ucs-realtime-push | WebSocket 实时推送 |
| 8084 | ucs-command | 指令下发与跟踪 |
| 8085 | ucs-drone-state | 无人机状态管理 |
| 8086 | ucs-business | 核心业务服务 |
| 9092 | Kafka | 消息队列 |
| 8090 | Kafka UI | Kafka 管理界面 |
| 5432 | PostgreSQL | 业务数据库 |
| 5433 | TimescaleDB | 遥测时序数据库 |
| 6379 | Redis | 缓存服务 |
| 5050 | DDS Gateway（可选） | DDS 指令接收 HTTP 端口 |

## 5. 后端微服务构建与启动

### 5.1 Maven 构建

微服务的 Dockerfile 基于 `eclipse-temurin:17-jre-alpine` 运行时镜像，需要先在宿主机编译出 JAR 包，再由 Docker 打包为容器镜像。

```bash
# 进入 ucs-platform 目录
cd ~/UCS_Dev/ucs-platform

# 编译打包所有模块（跳过测试，加速构建）
# 如果未安装 Maven，先安装：sudo apt install -y maven
mvn clean package -DskipTests

# 验证 JAR 包生成
ls -lh ucs-*/target/*.jar
```

**预期输出（每个可部署服务都有对应的 JAR）：**
```
ucs-api-gateway/target/ucs-api-gateway-2.0.0-SNAPSHOT.jar
ucs-business/target/ucs-business-2.0.0-SNAPSHOT.jar
ucs-command/target/ucs-command-2.0.0-SNAPSHOT.jar
ucs-drone-state/target/ucs-drone-state-2.0.0-SNAPSHOT.jar
ucs-realtime-push/target/ucs-realtime-push-2.0.0-SNAPSHOT.jar
ucs-telemetry-ingest/target/ucs-telemetry-ingest-2.0.0-SNAPSHOT.jar
ucs-telemetry-store/target/ucs-telemetry-store-2.0.0-SNAPSHOT.jar
```

> **注意：** `ucs-common` 是公共依赖模块，不生成可执行 JAR，其他模块通过 Maven 依赖引用它。

### 5.2 Docker Compose 一键启动

```bash
# 回到项目根目录
cd ~/UCS_Dev

# 一键构建镜像并启动所有服务（后台运行）
docker compose -f docker-compose-microservices.yml up -d --build

# 等待所有服务启动完毕（约 1-3 分钟）
# 查看实时日志
docker compose -f docker-compose-microservices.yml logs -f
```

> 按 `Ctrl+C` 退出日志查看（不影响后台运行的容器）。

### 5.3 服务启动顺序说明

Docker Compose 配置了 `depends_on` 和 `healthcheck`，确保按照依赖关系有序启动：

```
第 1 层（基础设施，并行启动）：
  ├── Kafka      — 等待 healthcheck 通过（broker 就绪）
  ├── Redis      — 等待 healthcheck 通过（PING 响应）
  ├── PostgreSQL — 等待 healthcheck 通过（pg_isready）
  └── TimescaleDB — 等待 healthcheck 通过（pg_isready）

第 2 层（微服务，基础设施就绪后启动）：
  ├── ucs-telemetry-ingest  — 依赖 Kafka + Redis
  ├── ucs-telemetry-store   — 依赖 Kafka + Redis + TimescaleDB
  ├── ucs-realtime-push     — 依赖 Kafka + Redis
  ├── ucs-command            — 依赖 Kafka + Redis
  ├── ucs-drone-state        — 依赖 Redis + PostgreSQL
  └── ucs-business           — 依赖 Kafka + PostgreSQL + Redis

第 3 层（网关，所有微服务启动后）：
  └── ucs-api-gateway        — 依赖上述全部微服务 + Redis
```

## 6. 前端启动

前端是基于 React + Vite + TypeScript 的单页应用，通过 Vite 开发服务器运行。

### 6.1 安装依赖

```bash
cd ~/UCS_Dev/frontend/ucs-dashboard

# 安装 Node.js 依赖
npm install
```

### 6.2 环境变量配置

项目根目录已有 `.env` 文件配置高德地图 Key。如需指定后端 API 地址（非本机部署时），创建 `.env.local`：

```bash
# 如果后端和前端在同一台机器上，不需要额外配置
# 前端会自动使用 window.location.hostname:8080 作为 API 地址

# 如果后端在不同机器上，创建 .env.local 指定后端地址：
# echo "VITE_API_URL=http://<后端机器IP>:8080" > .env.local
```

**环境变量说明：**

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `VITE_API_URL` | 自动检测 | 后端 API 网关地址。不设置时自动使用 `{当前页面域名}:8080` |
| `VITE_AMAP_KEY` | 已配置 | 高德地图 JS API Key |
| `VITE_AMAP_SECRET` | 已配置 | 高德地图安全密钥 |
| `VITE_BAIDU_MAP_AK` | 已内置默认值 | 百度 JSAPI Three 开发者密钥 |
| `VITE_3DTILES_URL` | 无 | 自定义倾斜摄影 3D Tiles 数据地址 |

### 6.3 开发模式启动（局域网可访问）

**关键：** 默认 `vite` 只监听 `localhost`，局域网其他机器无法访问。必须添加 `--host 0.0.0.0` 参数使其绑定到所有网络接口：

```bash
cd ~/UCS_Dev/frontend/ucs-dashboard

# 启动开发服务器，监听所有网络接口
npx vite --host 0.0.0.0

# 或者使用 npm 脚本（需要追加参数）
npm run dev -- --host 0.0.0.0
```

**启动成功后输出：**
```
  VITE v5.x.x  ready in xxx ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: http://<虚拟机IP>:5173/
```

> **局域网其他机器** 通过浏览器访问 `http://<虚拟机IP>:5173` 即可打开前端页面。

### 6.4 生产构建部署（可选）

如果需要生产环境部署（而非开发模式），可以构建静态文件后用 Nginx 托管：

```bash
# 构建生产版本
cd ~/UCS_Dev/frontend/ucs-dashboard
npm run build

# 构建产物在 dist/ 目录
ls dist/

# 使用 Nginx 托管（需要先安装 Nginx）
sudo apt install -y nginx

# 复制构建产物到 Nginx 目录
sudo cp -r dist/* /var/www/html/

# 配置 Nginx 反向代理（处理 SPA 路由 + API 代理）
sudo tee /etc/nginx/sites-available/ucs-dashboard > /dev/null << 'EOF'
server {
    listen 5173;
    server_name _;
    root /var/www/html;
    index index.html;

    # SPA 路由：所有非文件请求返回 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 反向代理到网关
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # WebSocket 反向代理
    location /ws/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
    }
}
EOF

sudo ln -sf /etc/nginx/sites-available/ucs-dashboard /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

## 7. DDS Gateway 启动（可选）

> DDS Gateway 是连接 PX4 无人机飞控与 UCS 平台的通信桥梁。如果只是测试平台基础功能（用户管理、任务创建等），可以跳过此步骤。只有在需要实际接入无人机仿真器或真机时才需要启动。

### 7.1 前置条件

```bash
# 1. 安装 ROS2 Humble（参考 https://docs.ros.org/en/humble/Installation.html）
# 确认 ROS2 环境已 source
source /opt/ros/humble/setup.bash

# 2. 安装 px4_msgs（ROS2 消息包）
sudo apt install -y ros-humble-px4-msgs

# 3. 安装 Python 依赖
cd ~/UCS_Dev/dds-gateway
pip install requests kafka-python redis
```

### 7.2 启动命令

```bash
cd ~/UCS_Dev/dds-gateway

# 确保 ROS2 环境已加载
source /opt/ros/humble/setup.bash

# 设置环境变量（指向 Docker 内的服务）
export UCS_BACKEND_URL=http://localhost:8080
export REDIS_HOST=localhost
export REDIS_PORT=6379
export KAFKA_BOOTSTRAP_SERVERS=localhost:9092

# 启动 DDS Gateway
python3 dds_gateway.py --verbose
```

**DDS Gateway 环境变量说明：**

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `UCS_BACKEND_URL` | `http://localhost:8080` | 后端 API 网关地址 |
| `REDIS_HOST` | `localhost` | Redis 地址 |
| `REDIS_PORT` | `6379` | Redis 端口 |
| `KAFKA_BOOTSTRAP_SERVERS` | `localhost:9092` | Kafka 地址 |
| `ROS_DOMAIN_ID` | `0` | ROS2 域 ID，需与 PX4 仿真器一致 |
| `DDS_COMMAND_PORT` | `5050` | 接收后端指令的 HTTP 端口 |

## 8. 基础功能测试

### 8.1 基础设施健康检查

```bash
# Kafka 检查：列出 Topic
docker exec ucs-kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:29092 --list

# Redis 检查：PING
docker exec ucs-redis redis-cli ping
# 预期输出: PONG

# PostgreSQL 检查：连接测试
docker exec ucs-postgres psql -U ucs -d ucs -c "SELECT count(*) FROM roles;"
# 预期输出: 表中有初始化数据

# TimescaleDB 检查：连接测试
docker exec ucs-timescaledb psql -U ucs -d ucs_telemetry -c "SELECT 1;"
# 预期输出: 1

# Kafka UI：浏览器访问
# http://<虚拟机IP>:8090
```

### 8.2 微服务健康检查

每个微服务都暴露了 Spring Boot Actuator 健康端点：

```bash
# API 网关
curl http://localhost:8080/actuator/health

# 遥测接入
curl http://localhost:8081/actuator/health

# 遥测存储
curl http://localhost:8082/actuator/health

# 实时推送
curl http://localhost:8083/actuator/health

# 指令下发
curl http://localhost:8084/actuator/health

# 无人机状态
curl http://localhost:8085/actuator/health

# 业务管理
curl http://localhost:8086/actuator/health
```

**预期返回：**
```json
{"status":"UP"}
```

**一键检查脚本：**
```bash
for port in 8080 8081 8082 8083 8084 8085 8086; do
    status=$(curl -s -o /dev/null -w "%{http_code}" http://localhost:$port/actuator/health 2>/dev/null)
    echo "Port $port: HTTP $status"
done
```

## 10. 常见问题排查

### Q1: Maven 构建失败，找不到 JDK 17

```bash
# 安装 JDK 17
sudo apt update
sudo apt install -y openjdk-17-jdk

# 确认版本
java -version
# 应显示: openjdk version "17.x.x"

# 如果系统有多个 JDK，设置默认版本
sudo update-alternatives --config java
```

### Q2: Docker Compose 启动失败，提示端口已被占用

```bash
# 查看占用端口的进程
sudo lsof -i :8080
# 或
sudo ss -tlnp | grep 8080

# 停止占用端口的进程后重新启动
docker compose -f docker-compose-microservices.yml up -d
```

### Q3: 微服务容器反复重启

```bash
# 查看具体服务的日志
docker logs ucs-business --tail 100

# 常见原因：
# 1. 数据库未就绪 — 等待 PostgreSQL/TimescaleDB healthcheck 通过
# 2. Kafka 未就绪 — 等待 Kafka healthcheck 通过
# 3. 数据库表不存在 — 确认 Doc/sql/ 下的初始化脚本已正确挂载

# 重新启动单个服务
docker compose -f docker-compose-microservices.yml restart ucs-business
```

### Q4: 前端页面白屏或 API 请求 502

```bash
# 1. 确认后端网关正常
curl http://localhost:8080/actuator/health

# 2. 检查前端 API 地址配置
# 浏览器 F12 → Console，查看 API 请求地址是否正确

# 3. 如果前端和后端不在同一台机器，需要设置 VITE_API_URL
echo "VITE_API_URL=http://<后端IP>:8080" > ~/UCS_Dev/frontend/ucs-dashboard/.env.local
# 然后重启前端开发服务器
```

### Q5: 局域网其他机器无法访问前端

```bash
# 1. 确认 vite 启动时使用了 --host 0.0.0.0
npx vite --host 0.0.0.0

# 2. 确认防火墙已放行端口
sudo ufw allow 5173/tcp
sudo ufw allow 8080/tcp

# 3. 确认虚拟机 IP 与访问者在同一子网
ip addr show
# 查看 eth0/ens* 接口的 IP 地址
```

### Q6: Kafka 消费者挂起，遥测数据未流转

```bash
# 查看 Kafka topic 列表
docker exec ucs-kafka /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server localhost:29092 --list

# 查看消费者组状态
docker exec ucs-kafka /opt/kafka/bin/kafka-consumer-groups.sh \
  --bootstrap-server localhost:29092 --list

# 查看特定消费者组详情
docker exec ucs-kafka /opt/kafka/bin/kafka-consumer-groups.sh \
  --bootstrap-server localhost:29092 \
  --group ucs-business --describe

# 通过 Kafka UI 查看：http://<虚拟机IP>:8090
```

### Q7: 数据库初始化脚本未执行

```bash
# PostgreSQL 初始化脚本只在首次启动（数据卷为空）时执行
# 如果需要重新初始化，删除数据卷后重新启动

docker compose -f docker-compose-microservices.yml down -v
docker compose -f docker-compose-microservices.yml up -d

# 手动执行初始化脚本
docker exec -i ucs-postgres psql -U ucs -d ucs < Doc/sql/01_postgres_schema.sql
docker exec -i ucs-postgres psql -U ucs -d ucs < Doc/sql/02_postgres_init_data.sql
docker exec -i ucs-timescaledb psql -U ucs -d ucs_telemetry < Doc/sql/03_timescaledb_init.sql
```
