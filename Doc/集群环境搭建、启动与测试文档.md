## 5. 第一步：基础设施启动（Kafka + Redis + PostgreSQL）

### 5.1 创建 Docker 网络

```bash
docker network create ucs_dev_kafka-net 2>/dev/null || true
```

### 5.2 启动 Kafka 3-Broker KRaft 集群

```bash
docker-compose -f docker-compose-kafka.yml up -d
```

**验证：**
```bash
# 等待30秒让集群初始化
sleep 30

# 检查3个Broker是否正常
docker exec kafka-1 kafka-metadata.sh --snapshot /tmp/kraft-combined-logs/__cluster_metadata-0/00000000000000000000.log --cluster-id $(docker exec kafka-1 cat /tmp/kraft-combined-logs/__cluster_metadata-0/.cluster_id 2>/dev/null || echo "unknown") 2>/dev/null || echo "Kafka brokers starting..."

# 列出 Topic（可能为空，说明集群正常）
docker exec kafka-1 kafka-topics.sh --list --bootstrap-server kafka-1:29092
```

### 5.3 启动 Redis 6节点集群

```bash
docker-compose -f docker-compose-redis-cluster.yml up -d
```

**验证：**
```bash
# 等待集群就绪
sleep 10

# 检查集群状态
docker exec redis-node-1 redis-cli -p 6371 cluster info | head -5
# 预期: cluster_state:ok, cluster_slots_assigned:16384
```

### 5.4 启动 PostgreSQL + TimescaleDB

```bash
docker-compose up -d postgres timescaledb
```

**验证：**
```bash
docker exec -it postgres psql -U ucs_user -d ucsdb -c "SELECT version();"
```

### 5.5 数据库初始化

首次部署需要执行 Flyway 迁移，后端启动时自动执行。如需手动：

```bash
cd backend
mvn flyway:migrate -Dflyway.url=jdbc:postgresql://localhost:5432/ucsdb \
    -Dflyway.user=ucs_user -Dflyway.password=ucs_password
```

## 10. K8s 部署（生产环境）

- K8s 集群（1.28+）已就绪
- kubectl 已配置 kubeconfig
- 镜像已推送到 Container Registry

### 10.3 验证

```bash

# 查看 HPA 状态
kubectl get hpa -n ucs

# 查看 Service
kubectl get svc -n ucs

# 查看后端日志
kubectl logs -f deployment/ucs-backend -n ucs

# 端口转发测试
kubectl port-forward svc/ucs-backend 8080:8080 -n ucs
```

| 资源            | 配置                                          |
|-----------------|-----------------------------------------------|

## 11. TLS 加密配置（生产环境）

### 11.1 生成自签名证书

```bash
cd scripts/tls
chmod +x generate-certs.sh
./generate-certs.sh
```

生成的文件：

| 文件路径                           | 用途                    |
|------------------------------------|------------------------|
| `certs/ca/ca-cert.pem`            | CA 根证书               |
| `certs/kafka/kafka-keystore.jks`  | Kafka Broker 密钥库     |
| `certs/kafka/kafka-truststore.jks`| Kafka 信任库            |
| `certs/redis/redis-cert.pem`      | Redis TLS 证书          |
| `certs/redis/redis-key.pem`       | Redis TLS 私钥          |

### 11.2 启用 Kafka TLS

1. 将 `kafka-keystore.jks` 和 `kafka-truststore.jks` 复制到 `backend/src/main/resources/`
2. 在 `application.properties` 中取消注释 TLS 配置：

```properties
spring.kafka.properties.security.protocol=SSL
spring.kafka.ssl.trust-store-location=classpath:kafka-truststore.jks
spring.kafka.ssl.trust-store-password=${KAFKA_SSL_TRUSTSTORE_PASS}
spring.kafka.ssl.key-store-location=classpath:kafka-keystore.jks
spring.kafka.ssl.key-store-password=${KAFKA_SSL_KEYSTORE_PASS}
```

### 11.3 启用 Redis TLS

在 `application.properties` 中取消注释：

```properties
spring.data.redis.ssl.enabled=true
```

> **生产环境务必替换自签名证书为正式 CA 签发的证书。**

## 12. Nacos 配置中心（可选）

### 12.1 启用 Nacos

设置环境变量后启动后端：

```bash
export NACOS_ENABLED=true
export NACOS_SERVER_ADDR=localhost:8848
export NACOS_NAMESPACE=ucs
java -jar target/ucs-backend-*.jar
```

### 12.2 在 Nacos 中添加配置

访问 Nacos 管理界面：`http://localhost:8848/nacos`（默认 nacos/nacos）

创建以下配置项（Properties 格式）：

**Data ID: `common-redis.properties`**
```properties
spring.data.redis.cluster.nodes=redis-node-1:6371,redis-node-2:6372,redis-node-3:6373,redis-node-4:6374,redis-node-5:6375,redis-node-6:6376
spring.data.redis.cluster.max-redirects=3
```

**Data ID: `common-kafka.properties`**
```properties
spring.kafka.bootstrap-servers=kafka-1:29092,kafka-2:29092,kafka-3:29092
```

### 12.3 动态刷新

修改 Nacos 配置后，后端会自动拉取新配置（`@RefreshScope` 标注的 Bean 会重新初始化），无需重启服务。

### ShedLock 验证（T-45）

启动两个后端实例后，观察日志中的定时任务执行情况：

```bash
# 实例1日志
grep "broadcastDroneSummary\|broadcastEvents\|reconcileDbRedis" instance1.log
```

预期：同一时刻只有一个实例执行定时任务，另一个实例因 ShedLock 跳过。

### 限流验证（T-47）

```bash
# 快速发送请求测试限流
for i in $(seq 1 120); do
  curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/api/control/command \
    -H "Content-Type: application/json" \
    -H "Authorization: Bearer <token>" \
    -d '{"uavId":"test","commandType":"HOLD"}' &
done
wait

# 预期：超过100QPS后返回429
```

### 幂等性验证（T-50）

```bash
# 连续发送相同命令
```

## 15. 常见问题排查

### Q1: Kafka 连接失败

**现象：** 后端日志 `Connection to node -1 could not be established`

**排查：**
```bash
# 检查 Kafka 容器是否运行
docker ps | grep kafka

# 检查网络连通性
docker exec backend ping kafka-1

# 检查 bootstrap-servers 配置
# Docker内部通信使用 kafka-1:29092（不是 localhost:9092）
```

**解决：** 确保 `KAFKA_BOOTSTRAP_SERVERS` 使用容器名 + 内部端口。

### Q2: Redis 集群连接失败

**现象：** `Unable to connect to Redis cluster`

**排查：**
```bash
# 检查 Redis 集群状态
docker exec redis-node-1 redis-cli -p 6371 cluster nodes

# 确认所有节点正常
docker exec redis-node-1 redis-cli -p 6371 cluster info | grep cluster_state
```

**解决：** 等待集群自动选主完成（通常30秒内）。

### Q3: ShedLock 未生效（定时任务重复执行）

**排查：**
```bash
# 检查 Redis 中 ShedLock 键
docker exec redis-node-1 redis-cli -p 6371 keys "shedlock:*"

# 检查是否引入了 shedlock 依赖
grep shedlock backend/pom.xml
```

**解决：** 确保 `@EnableSchedulerLock` 注解已添加且 Redis 连接正常。

### Q4: Prometheus 无法采集后端指标

**排查：**
```bash
# 确认 Actuator 端点可访问
curl http://localhost:8080/actuator/prometheus

# 检查 Prometheus 配置中的 target 地址
cat monitoring/prometheus.yml | grep targets
```

**解决：** 确保 Prometheus 容器能访问后端容器（同一 Docker 网络）。

### Q5: JWT RSA 模式未生效

**排查：**
```bash
# 确认环境变量已设置
echo $jwt.rsa.private-key
echo $jwt.rsa.public-key

# 如果为空，JWT 自动回退到 HMAC 模式（这是正常行为）
```

**生成 RSA 密钥对：**
```bash
# 生成 RSA 私钥
openssl genrsa -out private.pem 2048
# 提取公钥
openssl rsa -in private.pem -pubout -out public.pem
# Base64 编码（去掉头尾和换行）
cat private.pem | grep -v "BEGIN\|END" | tr -d '\n'
cat public.pem | grep -v "BEGIN\|END" | tr -d '\n'
```

### Q6: 前端 WebSocket 断连

**排查：**
- 检查浏览器控制台的 WebSocket 错误
- 确认后端 `/ws` 端点可访问
- 多实例模式下确认 Redis Broker 已启用

**解决：** 前端 StompConnectionManager 内置了自动重连机制（指数退避），通常等待即可自动恢复。

## 16. 安全配置（JWT RSA / 限流 / 幂等）

### T-46: JWT RSA 双模配置

| 模式   | 触发条件                                    | 适用场景         |
|--------|---------------------------------------------|------------------|
| RSA    | 设置 `jwt.rsa.private-key` 和 `public-key`  | 生产环境         |
| HMAC   | RSA 密钥为空（默认）                         | 开发/测试环境    |

### T-47: 限流配置

| 端点类别       | 限流阈值       | 配置项                     |
|----------------|----------------|----------------------------|
| 通用 API       | 100 QPS        | `ucs.rate-limit.default-qps` |
| 控制命令 API   | 10 QPS         | `ucs.rate-limit.command-qps`  |

超限返回 HTTP 429 + `ApiResponse{code:42900, message:"Too many requests"}`

### T-49: 熔断器配置

| 熔断器名称     | 滑动窗口 | 失败率阈值 | 半开等待时间 |
|----------------|----------|------------|-------------|
| redis          | 10       | 50%        | 30s         |
| gateway-http   | 5        | 60%        | 10s         |

### T-50: 幂等性配置

- **去重窗口：** 5秒
- **Key 格式：** `cmd:idempotent:{SHA256(uavId+commandType+params)}`
- **存储：** Redis SETNX + TTL
