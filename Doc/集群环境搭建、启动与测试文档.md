## 5. 第一步：基础设施启动（Kafka + Redis + PostgreSQL）

### 5.1 创建 Docker 网络

```bash
docker network create ucs_dev_kafka-net 2>/dev/null || true
```

### 5.2 启动 Kafka 3-Broker KRaft 集群

```bash
docker-compose -f docker-compose-kafka.yml up -d
```

**验证：**
```bash
# 等待30秒让集群初始化
sleep 30

# 检查3个Broker是否正常
docker exec kafka-1 kafka-metadata.sh --snapshot /tmp/kraft-combined-logs/__cluster_metadata-0/00000000000000000000.log --cluster-id $(docker exec kafka-1 cat /tmp/kraft-combined-logs/__cluster_metadata-0/.cluster_id 2>/dev/null || echo "unknown") 2>/dev/null || echo "Kafka brokers starting..."

# 列出 Topic（可能为空，说明集群正常）
docker exec kafka-1 kafka-topics.sh --list --bootstrap-server kafka-1:29092
```

### 5.3 启动 Redis 6节点集群

```bash
docker-compose -f docker-compose-redis-cluster.yml up -d
```

**验证：**
```bash
# 等待集群就绪
sleep 10

# 检查集群状态
docker exec redis-node-1 redis-cli -p 6371 cluster info | head -5
# 预期: cluster_state:ok, cluster_slots_assigned:16384
```

### 5.4 启动 PostgreSQL + TimescaleDB

```bash
docker-compose up -d postgres timescaledb
```

**验证：**
```bash
docker exec -it postgres psql -U ucs_user -d ucsdb -c "SELECT version();"
```

### 5.5 数据库初始化

首次部署需要执行 Flyway 迁移，后端启动时自动执行。如需手动：

```bash
cd backend
mvn flyway:migrate -Dflyway.url=jdbc:postgresql://localhost:5432/ucsdb \
    -Dflyway.user=ucs_user -Dflyway.password=ucs_password
```

| 微服务                 | 端口  | 说明                              |
|------------------------|-------|-----------------------------------|

| ucs-command            | 8084  | 命令调度（REST→Kafka Producer）   |
| ucs-drone-state        | 8085  | 无人机状态缓存（Redis + REST）    |
| ucs-business           | 8086  | 业务逻辑（用户/团队/任务/控制）   |

### 7.3 开发环境启动（逐个启动）

```bash
# 1. API网关（必须最先启动，负责路由和鉴权）
java -jar ucs-api-gateway/target/ucs-api-gateway-*.jar --spring.profiles.active=dev &

# 2. 业务服务（JWT签发、用户管理）
java -jar ucs-business/target/ucs-business-*.jar --spring.profiles.active=dev &

# 3. 遥测接入
java -jar ucs-telemetry-ingest/target/ucs-telemetry-ingest-*.jar --spring.profiles.active=dev &

# 4. 遥测存储
java -jar ucs-telemetry-store/target/ucs-telemetry-store-*.jar --spring.profiles.active=dev &

# 5. 实时推送
java -jar ucs-realtime-push/target/ucs-realtime-push-*.jar --spring.profiles.active=dev &

# 6. 命令调度
java -jar ucs-command/target/ucs-command-*.jar --spring.profiles.active=dev &

# 7. 无人机状态
java -jar ucs-drone-state/target/ucs-drone-state-*.jar --spring.profiles.active=dev &
```

### 7.4 多实例模拟（测试 ShedLock / WebSocket 多实例）

```bash
# ucs-business 实例2（端口8087）
java -jar ucs-business/target/ucs-business-*.jar --server.port=8087 --spring.profiles.active=prod &

# ucs-telemetry-ingest 实例2（端口8088）
java -jar ucs-telemetry-ingest/target/ucs-telemetry-ingest-*.jar --server.port=8088 --spring.profiles.active=prod &
```

> **注意：** 多实例模式下：
> - ShedLock（T-45）确保 ucs-business 定时任务只在一个实例执行
> - WebSocket 通过 Redis Pub/Sub（T-27）实现跨 ucs-realtime-push 实例消息分发
> - Kafka Consumer Group 自动在同一模块的多实例间分配 partition

### 7.5 验证各微服务健康

```bash
# 逐个检查所有微服务健康状态
for port in 8080 8081 8082 8083 8084 8085 8086; do
  echo "=== Port $port ==="
  curl -s http://localhost:$port/actuator/health | python3 -m json.tool 2>/dev/null || echo "FAILED"
```

| ucs-telemetry-ingest| 3      | 3~10    | 500m / 2000m   | 512Mi / 1024Mi   |
| ucs-telemetry-store | 2      | 2~6     | 500m / 2000m   | 512Mi / 1024Mi   |

## 11. TLS 加密配置（生产环境）

### 11.1 生成自签名证书

```bash
cd scripts/tls
chmod +x generate-certs.sh
./generate-certs.sh
```

生成的文件：

| 文件路径                           | 用途                    |
|------------------------------------|------------------------|
| `certs/ca/ca-cert.pem`            | CA 根证书               |
| `certs/kafka/kafka-keystore.jks`  | Kafka Broker 密钥库     |
| `certs/kafka/kafka-truststore.jks`| Kafka 信任库            |
| `certs/redis/redis-cert.pem`      | Redis TLS 证书          |
| `certs/redis/redis-key.pem`       | Redis TLS 私钥          |

### 11.2 启用 Kafka TLS

1. 将 `kafka-keystore.jks` 和 `kafka-truststore.jks` 复制到各微服务的 `src/main/resources/`
2. 在各模块 `application.yml` 中取消注释 TLS 配置：

```properties
spring.kafka.properties.security.protocol=SSL
spring.kafka.ssl.trust-store-location=classpath:kafka-truststore.jks
spring.kafka.ssl.trust-store-password=${KAFKA_SSL_TRUSTSTORE_PASS}
```

## 15. 常见问题排查

### Q1: Kafka 连接失败

**现象：** 后端日志 `Connection to node -1 could not be established`

**排查：**
```bash
# 检查 Kafka 容器是否运行
docker ps | grep kafka

# 检查网络连通性
docker exec backend ping kafka-1

# 检查 bootstrap-servers 配置
# Docker内部通信使用 kafka-1:29092（不是 localhost:9092）
```

**解决：** 确保 `KAFKA_BOOTSTRAP_SERVERS` 使用容器名 + 内部端口。

### Q2: Redis 集群连接失败

**现象：** `Unable to connect to Redis cluster`

**排查：**
```bash
# 检查 Redis 集群状态
docker exec redis-node-1 redis-cli -p 6371 cluster nodes

# 确认所有节点正常
docker exec redis-node-1 redis-cli -p 6371 cluster info | grep cluster_state
```

**解决：** 等待集群自动选主完成（通常30秒内）。

### Q3: ShedLock 未生效（定时任务重复执行）

**排查：**
```bash
# 检查 Redis 中 ShedLock 键
docker exec redis-node-1 redis-cli -p 6371 keys "shedlock:*"

# 检查是否引入了 shedlock 依赖
grep shedlock ucs-platform/ucs-business/pom.xml
```

**解决：** 确保 `@EnableSchedulerLock` 注解已添加且 Redis 连接正常。

### Q4: Prometheus 无法采集后端指标

**排查：**
```bash
# 确认 Actuator 端点可访问
curl http://localhost:8080/actuator/prometheus

# 检查 Prometheus 配置中的 target 地址
cat monitoring/prometheus.yml | grep targets
```

**解决：** 确保 Prometheus 容器能访问后端容器（同一 Docker 网络）。

### Q5: JWT RSA 模式未生效

**排查：**
```bash
# 确认环境变量已设置
echo $jwt.rsa.private-key
echo $jwt.rsa.public-key

# 如果为空，JWT 自动回退到 HMAC 模式（这是正常行为）
```

**生成 RSA 密钥对：**
```bash
# 生成 RSA 私钥
openssl genrsa -out private.pem 2048
# 提取公钥
openssl rsa -in private.pem -pubout -out public.pem
# Base64 编码（去掉头尾和换行）
cat private.pem | grep -v "BEGIN\|END" | tr -d '\n'
cat public.pem | grep -v "BEGIN\|END" | tr -d '\n'
```

### Q6: 前端 WebSocket 断连

**排查：**
- 检查浏览器控制台的 WebSocket 错误
- 确认后端 `/ws` 端点可访问
- 多实例模式下确认 Redis Broker 已启用

**解决：** 前端 StompConnectionManager 内置了自动重连机制（指数退避），通常等待即可自动恢复。

| 熔断器名称     | 滑动窗口 | 失败率阈值 | 半开等待时间 |

| gateway-http   | 5        | 60%        | 10s         |

- **去重窗口：** 5秒
- **Key 格式：** `cmd:idempotent:{SHA256(uavId+commandType+params)}`
- **存储：** Redis SETNX + TTL
