### 1.2 现有 UI 架构

当前系统有四个角色视图：

```
App.tsx (Observer 大屏视图, 2703行)
├── pages/CommanderView.tsx   (指挥官视图)
├── pages/LeaderView.tsx      (队长视图, 1403行)
├── pages/PilotView.tsx       (飞手视图)
└── components/MapPanel.tsx   (可复用地图组件, 1013行)
```

**核心问题**：
- `App.tsx` 单文件 2703 行，职责混乱，难以维护
- `LeaderView.tsx` 1403 行，状态管理复杂，嵌套层级深
- 地图标记使用原生 DOM 操作（`innerHTML`），与 React 生命周期脱节
- 弹窗逻辑分散（watchdog 机制、手动计时器），容易出现内存泄漏
- 无统一的设计 Token 系统，颜色/间距硬编码散落各处
- 缺乏暗色主题的视觉层次感，界面扁平、信息密度低
- 移动端适配缺失

### 1.4 核心痛点

1. **视觉层次缺失**：当前使用 Tailwind 默认配色，缺乏军事/工业风格的视觉语言
2. **信息密度不足**：大量空白区域，关键数据不够突出
3. **动效缺失**：状态变化无过渡动画，用户感知差
4. **组件耦合严重**：地图、列表、控制面板逻辑混在同一组件
5. **实时数据可视化弱**：仅有简单的 Recharts 图表，缺乏专业的数据大屏效果
6. **多实例 WebSocket 问题**：后端升级 Kafka + Redis Pub/Sub 后，前端需要适配新的推送架构

## 三、优化机会与替代方案分析

### 3.1 地图渲染层优化

#### 当前方案（MapLibre GL + DOM 标记）

```
当前实现:
  MapLibre GL 地图底图
  + maplibregl.Marker (DOM 元素, 每架无人机一个 div)
  + innerHTML 直接操作 DOM
  
问题:
  - 1000+ 无人机时 DOM 节点过多，性能急剧下降
  - 标记更新触发大量 reflow/repaint
  - 无法支持 10 万+ 无人机渲染
```

#### 方案 A：MapLibre GL Symbol Layer（推荐）

```
优化方案:
  MapLibre GL 地图底图
  + GeoJSON Source (所有无人机数据)
  + Symbol Layer (GPU 渲染, 支持 100 万+ 标记)
  + 自定义 SDF 图标 (支持旋转、颜色变化)

优势:
  ✅ GPU 渲染，10 万+ 无人机流畅
  ✅ 原生支持图标旋转 (icon-rotate 属性)
  ✅ 数据驱动样式 (armed 状态 → 颜色变化)
  ✅ 聚合 (Cluster) 原生支持
  ✅ 与现有 MapLibre 技术栈完全兼容

实现要点:
  map.addSource('drones', {
    type: 'geojson',
    data: { type: 'FeatureCollection', features: [] },
    cluster: true,           // 自动聚合
    clusterMaxZoom: 14,
    clusterRadius: 50
  });
  
  map.addLayer({
    id: 'drone-layer',
    type: 'symbol',
    source: 'drones',
    layout: {
      'icon-image': ['case', ['get', 'armed'], 'drone-armed', 'drone-idle'],
      'icon-rotate': ['get', 'heading'],  // 直接使用 heading 属性旋转
      'icon-rotation-alignment': 'map',
      'icon-size': ['interpolate', ['linear'], ['zoom'], 8, 0.3, 16, 1.0]
    },
    paint: {
      'icon-color': ['case',
        ['!', ['get', 'online']], '#6b7280',  // 离线: 灰色
        ['get', 'armed'], '#00F0FF',           // 飞行中: 青色
        '#7FFFD4'                              // 待机: 水绿
      ],
      'icon-opacity': ['case', ['get', 'online'], 1.0, 0.4]
    }
  });
```

#### 方案 B：deck.gl ScatterplotLayer（超大规模备选）

```
适用场景: 千万级无人机（Phase 4）

deck.gl IconLayer:
  - WebGL2 渲染，理论支持千万级标记
  - 与 MapLibre GL 集成 (MapboxOverlay)
  - 支持实例化渲染 (Instanced Rendering)

缺点:
  - 引入额外依赖 (deck.gl ~2MB)
  - 与现有 MapLibre 事件系统集成复杂
  - 学习成本较高

推荐: Phase 1-3 使用方案 A，Phase 4 (千万级) 升级到方案 B
```

#### 方案 C：Three.js WebGL 自定义层（最高性能）

```
适用场景: 需要 3D 效果 + 千万级渲染

MapLibre GL CustomLayer + Three.js:
  - 完全自定义 WebGL 渲染管线
  - 支持 3D 无人机模型、飞行轨迹粒子效果
  - 性能最优，但开发成本最高

推荐: 仅在有明确 3D 可视化需求时采用
```

**结论**：**推荐方案 A（MapLibre GL Symbol Layer）**，与现有技术栈完全兼容，性能提升 10-100 倍，开发成本最低。

### 3.2 状态管理优化

#### 当前方案（React useState 分散管理）

```
问题:
  - LeaderView.tsx 中有 30+ 个 useState
  - 状态提升导致 prop drilling
  - WebSocket 数据直接触发 setState，导致频繁重渲染
  - 无法跨组件共享实时遥测数据
```

#### 推荐方案：Zustand + React Query

```typescript
// stores/droneStore.ts
import { create } from 'zustand';
import { subscribeWithSelector } from 'zustand/middleware';

interface DroneStore {
  // 实时遥测数据 (WebSocket 驱动)
  drones: Map<string, DroneState>;
  updateDrone: (uavId: string, data: Partial<DroneState>) => void;
  removeDrone: (uavId: string) => void;
  
  // UI 状态
  selectedDroneId: string | null;
  selectedDroneIds: Set<string>;
  multiSelectMode: boolean;
  
  // 视口状态
  viewport: ViewportBounds | null;
  setViewport: (bounds: ViewportBounds) => void;
}

const useDroneStore = create<DroneStore>()(
  subscribeWithSelector((set) => ({
    drones: new Map(),
    updateDrone: (uavId, data) => set(state => {
      const newDrones = new Map(state.drones);
      newDrones.set(uavId, { ...newDrones.get(uavId), ...data } as DroneState);
      return { drones: newDrones };
    }),
    // ...
  }))
);

// 选择器优化：只订阅需要的数据切片
const droneCount = useDroneStore(state => state.drones.size);
const selectedDrone = useDroneStore(state => 
  state.selectedDroneId ? state.drones.get(state.selectedDroneId) : null
);
```

**优势**：
- 避免不必要的重渲染（精细化订阅）
- WebSocket 数据直接写入 Store，不触发全量重渲染
- 跨组件共享状态无需 prop drilling

### 3.5 大规模列表渲染

#### 当前方案（全量渲染）

```
问题:
  - 无人机列表直接 .map() 渲染所有条目
  - 1000+ 无人机时页面卡顿
```

#### 推荐方案：TanStack Virtual（虚拟化）

```typescript
import { useVirtualizer } from '@tanstack/react-virtual';

function DroneList({ drones }: { drones: DroneState[] }) {
  const parentRef = useRef<HTMLDivElement>(null);
  
  const virtualizer = useVirtualizer({
    count: drones.length,
    getScrollElement: () => parentRef.current,
    estimateSize: () => 64,  // 每行高度
    overscan: 5,             // 预渲染行数
  });

  return (
    <div ref={parentRef} style={{ height: '100%', overflow: 'auto' }}>
      <div style={{ height: virtualizer.getTotalSize() }}>
        {virtualizer.getVirtualItems().map(virtualItem => (
          <DroneListItem
            key={drones[virtualItem.index].uavId}
            drone={drones[virtualItem.index]}
            style={{ transform: `translateY(${virtualItem.start}px)` }}
          />
        ))}
      </div>
    </div>
  );
}
```

**优势**：支持 10 万+ 条目流畅滚动，DOM 节点数量恒定（仅渲染可见区域）。

```typescript
// 升级后: 通过 Spring Cloud Gateway 连接，后端使用 Redis Pub/Sub
// 前端代码无需大改，只需确保连接到 API Gateway

// 新增: 连接状态感知 + 自动重连
const useWebSocketWithResilience = () => {
  const [connectionState, setConnectionState] = useState<
    'connecting' | 'connected' | 'reconnecting' | 'failed'
  >('connecting');
  
  // 指数退避重连
  const reconnectDelay = useRef(1000);
  
  const onConnect = () => {
    setConnectionState('connected');
    reconnectDelay.current = 1000; // 重置退避时间
  };
  
  const onDisconnect = () => {
    setConnectionState('reconnecting');
    reconnectDelay.current = Math.min(reconnectDelay.current * 2, 30000);
  };
  
  // 新增: 连接状态指示器 UI
  return { connectionState };
};

// 新增: Epoch 感知 — 展示过期消息警告
const useEpochAwareness = () => {
  const [staleCount, setStaleCount] = useState(0);
  
  const onStaleMessage = (uavId: string) => {
    setStaleCount(c => c + 1);
    // 在 UI 上短暂显示"数据重置"提示
  };
  
  return { staleCount, onStaleMessage };
};
```

## 八、性能优化策略

### 8.1 渲染性能

| 优化项 | 当前问题 | 解决方案 | 预期收益 |
|--------|---------|---------|---------|
| 地图标记 | DOM Marker，1000+ 卡顿 | Symbol Layer（GPU 渲染） | 支持 10 万+ |
| 无人机列表 | 全量渲染 | TanStack Virtual | 支持 10 万+ 条目 |
| 状态更新 | useState 触发全量重渲染 | Zustand 精细化订阅 | 减少 80% 重渲染 |
| WebSocket 数据 | 每条消息 setState | 10Hz 缓冲刷新（已实现） | 减少 90% 重渲染 |
| 图表更新 | Recharts 全量重渲染 | ECharts appendData | 流式更新，无重渲染 |

### 8.2 网络性能

| 优化项 | 当前问题 | 解决方案 |
|--------|---------|---------|
| 视口裁剪 | 推送所有无人机数据 | useViewportClipping（已实现，需集成） |
| 降采样 | 固定 10Hz 推送 | 根据缩放级别动态调整（已实现） |
| 数据压缩 | JSON 明文 | 后端 Kafka LZ4 压缩（已规划） |
| 断线重连 | 固定 5s 重连 | 指数退避（1s→2s→4s→...→30s） |

## 十一、技术选型对比与推荐

### 11.1 综合技术选型表

| 类别 | 当前方案 | 推荐方案 | 替代方案 | 推荐理由 |
|------|---------|---------|---------|---------|
| **地图标记渲染** | DOM Marker | **MapLibre Symbol Layer** | deck.gl IconLayer | 与现有技术栈兼容，性能提升 100 倍 |
| **状态管理** | React useState | **Zustand** | Jotai / Redux Toolkit | 轻量、精细化订阅、无 Provider 嵌套 |
| **服务端状态** | 手动 fetch + setInterval | **React Query** | SWR | 缓存、重试、后台刷新开箱即用 |
| **数据可视化** | Recharts (SVG) | **ECharts** | D3.js | Canvas 渲染、流式更新、主题定制 |
| **动效库** | CSS Transition | **Framer Motion** | React Spring | 布局动画、手势、与 React 深度集成 |
| **列表虚拟化** | 全量渲染 | **TanStack Virtual** | react-window | 支持动态高度、与 React 18 兼容 |
| **字体** | 系统字体 | **Orbitron + Inter** | — | Orbitron 科技感强，Inter 可读性好 |
| **图标** | Lucide React | **Lucide React（保留）** | — | 已有，风格统一，无需替换 |
| **动画背景** | 无 | **Canvas 粒子（自实现）** | tsparticles | 轻量，完全可控，无额外依赖 |
