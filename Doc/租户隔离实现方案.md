# 租户隔离实现方案

> 版本: v1.0 | 日期: 2024-01 | 状态: 方案设计阶段

---

## 一、现状分析

### 1.1 当前隔离模型

当前系统实现了 **分区级（Partition-Level）数据隔离**，但 **未实现租户级（Tenant-Level）隔离**。

```
当前模型:
┌─────────────────────────────────────────┐
│              UCS 平台（单租户）            │
│                                         │
│  Team A          Team B          Team C │
│  ┌─────┐        ┌─────┐        ┌─────┐ │
│  │User1│        │User3│        │User5│ │
│  │User2│        │User4│        │User6│ │
│  └──┬──┘        └──┬──┘        └──┬──┘ │
│     │               │               │   │
│  Partition       Partition       Partition│
│  "zs_1"         "ls_3"         "ww_5"  │
│  "observer"     "observer"     "observer"│
│  "commander"    "commander"    "commander"│
└─────────────────────────────────────────┘
```

**现有隔离机制（源码级证据）：**

| 隔离层 | 实现方式 | 代码位置 | 隔离粒度 |
|--------|----------|----------|----------|
| WebSocket 数据推送 | 按 partition 分发 | `WebSocketGatewayService.broadcastToPartitions()` | 用户级 |
| 无人机可见性 | drone_partition_map 映射表 | `PartitionRoutingService.getPartitionsForDrone()` | 分区级 |
| 用户分区分配 | 登录时计算 partition_name | `AuthService.login()` → `PartitionNameUtil` | 用户级 |
| RBAC 权限控制 | Spring Security + 角色注解 | `SecurityConfig.securityFilterChain()` | 角色级 |

### 1.2 问题：缺少租户维度

```
问题场景:
┌──────────────────────────────────────────────┐
│ 企业A 和 企业B 共享同一个 UCS 实例            │
│                                              │
│ 企业A的管理员 能看到 企业B的无人机列表？       │ ← 不应该！
│ 企业A的指挥官 能向 企业B的无人机发送指令？     │ ← 不应该！
│ 企业A的数据 和 企业B的数据 混在同一张表？      │ ← 运维风险！
└──────────────────────────────────────────────┘
```

**核心差距：**

| 维度 | 当前状态 | 目标状态 |
|------|----------|----------|
| 数据库 | 所有租户共享表 | 行级租户过滤 或 Schema隔离 |
| API 层 | 无租户上下文 | 每个请求自动注入 tenantId |
| 无人机归属 | 仅分区映射 | 无人机绑定租户 |
| 用户归属 | team_id（团队级） | tenant_id（租户级）+ team_id |
| 数据查询 | 无租户过滤 | 所有查询自动 WHERE tenant_id = ? |

## 二、方案设计

### 2.1 租户模型选型

| 方案 | 隔离级别 | 复杂度 | 性能 | 适用场景 |
|------|----------|--------|------|----------|
| **共享表 + 行级过滤** | 低 | 低 | 高 | SaaS 早期，租户数 < 1000 |
| Schema 隔离 | 中 | 中 | 中 | 中等规模，对隔离有要求 |
| 独立数据库 | 高 | 高 | 高 | 大型企业，强合规需求 |

**推荐方案：共享表 + 行级过滤（Phase 1）**

理由：
1. 当前项目处于早期阶段，租户数量有限
2. 改造成本最低，只需添加 `tenant_id` 字段
3. 可平滑升级到 Schema 隔离（Phase 2）
4. Spring Data JPA 的 `@Filter` + Hibernate Filter 可自动注入

### 2.2 数据库 Schema 变更

```sql
-- ==========================================
-- Step 1: 创建租户表
-- ==========================================
CREATE TABLE tenants (
    id              BIGSERIAL PRIMARY KEY,
    tenant_code     VARCHAR(50) NOT NULL UNIQUE,  -- 租户编码（如 "org_001"）
    tenant_name     VARCHAR(200) NOT NULL,         -- 租户名称
    contact_name    VARCHAR(100),                   -- 联系人
    contact_phone   VARCHAR(20),                    -- 联系电话
    max_drones      INT DEFAULT 100,                -- 最大无人机数量
    max_users       INT DEFAULT 50,                 -- 最大用户数
    status          INT DEFAULT 1,                  -- 1=活跃, 0=禁用
    created_at      TIMESTAMP DEFAULT NOW(),
    updated_at      TIMESTAMP DEFAULT NOW()
);

-- ==========================================
-- Step 2: 为现有表添加 tenant_id 字段
-- ==========================================
ALTER TABLE users ADD COLUMN tenant_id BIGINT REFERENCES tenants(id);
ALTER TABLE teams ADD COLUMN tenant_id BIGINT REFERENCES tenants(id);
ALTER TABLE drones ADD COLUMN tenant_id BIGINT REFERENCES tenants(id);
ALTER TABLE events ADD COLUMN tenant_id BIGINT REFERENCES tenants(id);
ALTER TABLE drone_partition_map ADD COLUMN tenant_id BIGINT REFERENCES tenants(id);
ALTER TABLE command_logs ADD COLUMN tenant_id BIGINT REFERENCES tenants(id);
ALTER TABLE rally_points ADD COLUMN tenant_id BIGINT REFERENCES tenants(id);

-- ==========================================
-- Step 3: 为已有数据设置默认租户
-- ==========================================
INSERT INTO tenants (tenant_code, tenant_name) VALUES ('default', '默认租户');

UPDATE users SET tenant_id = 1 WHERE tenant_id IS NULL;
UPDATE teams SET tenant_id = 1 WHERE tenant_id IS NULL;
UPDATE drones SET tenant_id = 1 WHERE tenant_id IS NULL;
UPDATE events SET tenant_id = 1 WHERE tenant_id IS NULL;

-- ==========================================
-- Step 4: 创建索引（加速租户过滤查询）
-- ==========================================
CREATE INDEX idx_users_tenant ON users(tenant_id);
CREATE INDEX idx_teams_tenant ON teams(tenant_id);
CREATE INDEX idx_drones_tenant ON drones(tenant_id);
CREATE INDEX idx_events_tenant ON events(tenant_id);
CREATE INDEX idx_command_logs_tenant ON command_logs(tenant_id);
CREATE INDEX idx_rally_points_tenant ON rally_points(tenant_id);

-- ==========================================
-- Step 5: 设置 NOT NULL 约束（数据迁移完成后）
-- ==========================================
ALTER TABLE users ALTER COLUMN tenant_id SET NOT NULL;
ALTER TABLE teams ALTER COLUMN tenant_id SET NOT NULL;
ALTER TABLE drones ALTER COLUMN tenant_id SET NOT NULL;
```

### 2.3 应用层改造

#### 2.3.1 新增实体：Tenant

```java
@Data
@Entity
@Table(name = "tenants")
public class Tenant {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    
    @Column(name = "tenant_code", nullable = false, unique = true)
    private String tenantCode;
    
    @Column(name = "tenant_name", nullable = false)
    private String tenantName;
    
    @Column(name = "max_drones")
    private Integer maxDrones = 100;
    
    @Column(name = "max_users")
    private Integer maxUsers = 50;
    
    @Column
    private Integer status = 1;
}
```

#### 2.3.2 租户上下文传播

```java
/**
 * 租户上下文 — ThreadLocal 存储当前请求的 tenantId。
 * 
 * 生命周期: Filter 设置 → Service 层使用 → Filter 清除
 */
public class TenantContext {
    private static final ThreadLocal<Long> CURRENT_TENANT = new ThreadLocal<>();
    
    public static void setTenantId(Long tenantId) {
        CURRENT_TENANT.set(tenantId);
    }
    
    public static Long getTenantId() {
        return CURRENT_TENANT.get();
    }
    
    public static void clear() {
        CURRENT_TENANT.remove();
    }
}
```

#### 2.3.3 租户过滤器

```java
/**
 * 从 JWT 中提取 tenantId，设置到 TenantContext。
 * 在 JwtAuthenticationFilter 之后执行。
 */
@Component
@Order(2)
public class TenantFilter extends OncePerRequestFilter {
    
    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                     HttpServletResponse response,
                                     FilterChain filterChain) {
        try {
            Authentication auth = SecurityContextHolder.getContext().getAuthentication();
            if (auth != null && auth.getPrincipal() instanceof UserPrincipal principal) {
                TenantContext.setTenantId(principal.getTenantId());
            }
            filterChain.doFilter(request, response);
        } finally {
            TenantContext.clear();  // 必须清除，防止线程池复用导致数据泄露
        }
    }
}
```

#### 2.3.4 Hibernate 自动过滤

```java
// 方案 A: 使用 Hibernate @Filter（推荐）
@Entity
@Table(name = "drones")
@FilterDef(name = "tenantFilter", parameters = @ParamDef(name = "tenantId", type = Long.class))
@Filter(name = "tenantFilter", condition = "tenant_id = :tenantId")
public class Drone {
    @Column(name = "tenant_id")
    private Long tenantId;
    // ...
}

// 在 Repository 或 Service 层启用 Filter:
@Component
public class TenantAwareAspect {
    @PersistenceContext
    private EntityManager entityManager;
    
    @Before("execution(* com.ucs.repository.*.*(..))")
    public void enableTenantFilter() {
        Long tenantId = TenantContext.getTenantId();
        if (tenantId != null) {
            Session session = entityManager.unwrap(Session.class);
            session.enableFilter("tenantFilter").setParameter("tenantId", tenantId);
        }
    }
}
```

#### 2.3.5 JWT Token 中添加 tenantId

```java
// JwtUtil.buildToken() 中添加:
.claim("tenantId", tenantId)

// JwtUtil 中提取:
public Long extractTenantId(String token) {
    return extractClaim(token, claims -> claims.get("tenantId", Long.class));
}
```

### 2.4 Kafka 消息租户隔离

```
方案 A: Topic 级隔离（推荐小租户数）
  telemetry.raw.tenant_001
  telemetry.raw.tenant_002
  
方案 B: 消息头级隔离（推荐大租户数）
  Topic: telemetry.raw
  Header: X-Tenant-Id = tenant_001
  Consumer 按 header 过滤
```

推荐 **方案 B**（消息头级隔离），理由：
- Topic 数量不随租户数增长
- 更容易管理和监控
- Consumer Group 可按需过滤

## 四、为什么当前阶段不适合实现

| 原因 | 说明 |
|------|------|
| **改动面过大** | 涉及所有实体、所有 Repository、所有 Service 的查询方法 |
| **与 Kafka 改造冲突** | Kafka Phase 1 正在修改数据流路径，同时改租户会增加合并冲突 |
| **需要数据迁移** | 现有数据需要分配默认租户，需要停机维护窗口 |
| **测试覆盖不足** | 当前项目无自动化测试，租户隔离的正确性难以验证 |
| **前端未就绪** | 前端需要配合改造（登录流程、数据展示、权限控制） |

**建议实施时机：Phase 2（微服务拆分）之后**，此时：
- 微服务已拆分，每个服务独立改造，风险可控
- 数据层已升级（TimescaleDB），Schema 变更更方便
- 自动化测试已建立，可验证隔离正确性

## 六、常见疑问

### Q1: 为什么不直接用 Team 当租户？

> **Team 是租户内部的组织单元**，而非租户本身。一个企业（租户）可能有多个团队（Team）。如果用 Team 当租户，后续企业间的团队协作就无法实现。

### Q2: 租户隔离和分区隔离有什么区别？

> - **分区隔离（Partition）**：控制用户能看到哪些无人机的数据，是功能级隔离
> - **租户隔离（Tenant）**：控制不同组织的数据完全不可见，是安全级隔离
> - 两者是正交的：租户 A 内部仍然使用分区机制管理用户权限

### Q3: 行级过滤会不会影响性能？

> 添加 `tenant_id` 索引后，WHERE tenant_id = ? 的查询开销约 O(1)（索引查找）。实际测试中，百万级数据下性能差异 < 5%。

### Q4: 现有数据怎么迁移？

> 创建一个默认租户（tenant_code='default'），将所有现有数据的 tenant_id 设为默认租户 ID。迁移脚本见 2.2 节。
